# Golden Set v3 공식 RAGAS 저점 문항 분석

## 요약

Golden Set v3의 104문항을 대상으로 공식 RAGAS 평가를 수행한 결과, **Faithfulness는 0.6047(60.47%)**, **Answer Relevancy는 0.3077(30.77%)**로 측정됐다. 검색 근거와 답변 내용의 일치도보다 질문에서 요구한 내용을 빠짐없이 직접 답하는 능력이 더 취약한 것으로 나타났다.

가장 큰 문제는 **답변 가능한 질문을 잘못 거절한 경우**다. AI가 답변을 거절한 17문항 중 10문항은 Golden Set 기준으로 답변 가능한 질문이었다. 인용이 없는 17개 답변은 Answer Relevancy가 모두 0점이었으며, Faithfulness도 평균 0.235에 그쳤다.

두 번째 문제는 예산, 기간, 입찰방법처럼 여러 항목을 한 번에 묻는 **Multihop 질문의 일부 항목 누락**이다. 답변에 포함된 내용은 문서와 일치하더라도 질문에서 요구한 항목 하나가 빠지면 Answer Relevancy가 크게 낮아졌다.

세 번째 문제는 정확한 수치, 기간, 법적 근거 또는 전체 기능 목록이 포함된 청크를 찾지 못하고 관련 용어가 들어간 주변 청크로 답변한 경우다. 특히 인천광역시 문서와 스포츠윤리센터 문서에서 Faithfulness가 각각 0.407과 0.437로 낮게 나타났다.

구어체 질문은 Faithfulness가 0.793으로 가장 높았지만 Answer Relevancy는 0.096으로 가장 낮았다. 실제 답을 포함하고도 “다만”, “직접적으로 명시되지 않았다”와 같은 방어적 설명을 먼저 제시해 답변의 직접성이 낮아진 것이 주요 원인이다.

우선 개선 방향은 다음과 같다.

1. 질문을 금액, 기간, 조건, 법적 근거 등의 답변 슬롯으로 분해한다.
2. 일부 근거만 발견돼도 전체 답변을 거절하지 않고 확인된 항목과 미확인 항목을 구분한다.
3. 답변 첫 부분에서 질문의 핵심 수치와 조건을 직접 제시한다.
4. Multihop 질문은 하위 질문별 검색 결과를 합치고 각 항목에 인용을 연결한다.
5. 잘못 거절한 10문항을 대상으로 Retriever 실패와 Generation 판정 실패를 구분한다.

현재 결과는 향후 검색 및 생성 파이프라인 개선 효과를 비교하기 위한 **1차 baseline**으로 사용한다.

## 2. 가장 큰 문제: 답변 가능한 질문의 잘못된 거절

| Golden 기준 | AI 판단 | 문항 수 | Faithfulness | Answer Relevancy |
|---|---|---:|---:|---:|
| 답변 가능 | 답변함 | 85 | 0.669 | 0.369 |
| 답변 가능 | 답변 거절 | 10 | 0.200 | 0.000 |
| 답변 불가 | 답변함 | 2 | 1.000 | 0.302 |
| 답변 불가 | 답변 거절 | 7 | 0.286 | 0.000 |

AI가 답변을 거절한 문항은 총 17개다. 이 중 10개는 Golden Set 기준으로 답변 가능한 질문이다.

대표 사례는 다음과 같다.

- 오류 메시지를 몇 초 이내에 제시해야 하는가
- 위원회 임시계정 발급 기능의 목적은 무엇인가
- 외부 위원에게 임시 아이디를 어떤 방식으로 제공해야 하는가
- 미디어 플레이어 개선 범위에 포함되는 기능은 무엇인가
- 사업의 법적 근거가 되는 법률 조항은 무엇인가

거절 답변에는 인용이 없으며 대부분 다음 문구가 사용됐다.

```text
제공된 문서 근거만으로는 답변하기 어렵습니다.
```

이 답변들은 Answer Relevancy에서 모두 0점을 받았다.

## 3. 복수 요구사항 질문의 일부 항목 누락

`multihop` 질문은 한 질문에서 여러 항목을 동시에 요구한다.

- 문항 수: 48개
- Faithfulness: 0.579
- Answer Relevancy: 0.343

대표적인 질문 형태는 다음과 같다.

- 예산, 사업기간, 입찰방법을 모두 나열
- 입찰방법, 기술·가격 평가 비율, 추진일정을 함께 설명
- 총사업비 구성 항목과 공동수급 지분율을 함께 설명
- 연계해야 하는 시스템을 모두 나열
- 개선 대상 기능을 모두 나열

답변 내용이 문서 근거와 일치하더라도 질문에서 요구한 항목 중 하나가 빠지면 Answer Relevancy가 낮아졌다.

예를 들어 `한영대학_q004`의 결과는 다음과 같다.

- Faithfulness: 0.778
- Answer Relevancy: 0.000

입찰방법과 기술·가격 평가 비율에는 답했지만, 질문에서 함께 요구한 추진일정이 충분히 포함되지 않은 것이 주요 원인으로 보인다.

구어체 질문은 Faithfulness가 가장 높지만 Answer Relevancy는 가장 낮다.

구어체 질문의 예시는 다음과 같다.

실제 금액이나 기간이 답변에 포함돼도 다음과 같은 방어적 표현이 먼저 제시됐다.


이러한 표현은 질문에 대한 직접성을 떨어뜨려 Answer Relevancy가 낮아지는 원인이 된다.

## 9. 원인 요약

낮은 점수의 주요 원인은 다음 순서로 정리할 수 있다.

1. 답변 가능한 질문 10개를 잘못 거절함
2. 복수 요구사항 질문에서 일부 항목을 누락함
3. 정확한 수치, 기간, 법적 근거가 포함된 청크를 검색하지 못함
4. 질문에 직접 답하지 않고 방어적 단서와 일반 설명을 먼저 제시함
5. 관련성이 낮은 인용을 여러 개 사용함

## 10. 개선 우선순위

### 10.1 생성 단계

1. 질문을 예산, 기간, 조건, 기관, 법적 근거 등의 답변 슬롯으로 분해한다.
2. 각 슬롯에 대한 근거 존재 여부를 개별 판정한다.
3. 일부 슬롯의 근거만 발견돼도 전체 답변을 거절하지 않는다.
4. 첫 문장부터 금액, 기간 또는 조건을 직접 제시한다.
5. 각 답변 슬롯에 실제 근거 인용을 연결한다.
6. 생성 후 질문에서 요구한 항목이 모두 포함됐는지 검사한다.

### 10.2 검색 단계

1. 잘못 거절한 10문항의 검색 결과를 개별 조사한다.
2. Retriever 실패와 Generation 판정 실패를 구분한다.
3. 수치, 기간, 요구사항 번호에는 BM25 결과를 우선 활용한다.
4. Multihop 질문은 하위 질문별로 검색한 결과를 합친다.
5. 관련성이 낮은 청크를 인용 후보에서 제거한다.

### 10.3 평가 단계

1. 개선 전 현재 결과를 baseline으로 보존한다.
2. 동일한 Golden Set v3로 검색 평가를 재실행한다.
3. 같은 104문항의 답변을 다시 생성한다.
4. 동일한 공식 RAGAS 설정으로 재평가한다.
5. 전체 평균뿐 아니라 오거절, 질문 유형, 문서별 개선 폭을 비교한다.
