# UI RAG 부분 답변 및 오거절 문제 분석

## 요약

RAGAS 평가에 사용한 9개 PDF를 사용자 앱에 동일하게 적용한 뒤 Golden Set 질문을 UI에서 다시 질의한 결과, 문서에 실제 답이 존재하는데도 다음 문제가 재현됐다.

- 질문에서 요구한 항목 중 일부만 답변함
- 문서에 답이 있지만 근거가 없다고 판단함
- 사용자가 기술용어 대신 일반 표현이나 유사어를 사용하면 관련 내용을 찾지 못함
- 여러 항목 중 하나를 찾지 못하면 전체 질문에 대한 답변을 거절함

이 현상은 PDF 누락이나 화면 표시 문제라기보다 **검색 질의 구성, 용어 확장, 복수 항목 검색 및 답변 가능 여부 판정 방식**에서 발생한다. 공식 RAGAS 평가에서 확인된 낮은 Answer Relevancy와 답변 가능한 문항 10개의 오거절 문제도 동일한 원인으로 볼 수 있다.

## 1. 검색 결과 수 부족

현재 UI 답변은 기본적으로 검색 상위 5개 청크를 사용한다.

질문이 다음처럼 여러 항목을 동시에 요구하면 하나의 검색 질의로 모든 근거를 찾기 어렵다.

```text
이 사업의 총예산, 사업기간, 입찰방법은 무엇인가?
```

예산, 사업기간, 입찰방법이 서로 다른 페이지나 섹션에 있으면 상위 5개 검색 결과에 일부 항목의 청크만 포함될 수 있다.

이 경우 LLM은 검색된 항목만 답하거나, 근거가 충분하지 않다고 판단해 전체 답변을 거절할 수 있다.

## 2. 사용자 표현과 문서 표현의 차이

사용자 질문과 RFP 문서가 동일한 의미를 서로 다른 용어로 표현할 수 있다.

### 유지보수 관련 표현

사용자 질문:

```text
유지보수 기간은 얼마인가?
```

문서 표현 예시:

- 무상 하자보수
- 무상 유지관리
- 검수 완료 후 지원
- 안정화 지원기간
- 하자담보 책임기간

### 예산 관련 표현

사용자 질문:

```text
예산이 얼마인가?
```

문서 표현 예시:

- 사업비
- 총사업비
- 소요예산
- 추정가격
- 계약금액
- 배정예산

### 사업기간 관련 표현

사용자 질문:

```text
사업기간은 얼마나 되는가?
```

문서 표현 예시:

- 과업기간
- 계약기간
- 수행기간
- 착수일로부터 365일
- 계약일로부터 12개월

현재 Dense 검색의 Golden Set 성능은 BM25보다 낮고, BM25는 질문과 문서의 단어가 직접 일치할 때 강하다. 따라서 기술용어, 약어 또는 유사 표현이 다르면 검색 성능이 낮아질 수 있다.

## 3. 복수 항목 질문을 하나의 질의로 검색

현재는 질문 전체를 하나의 검색어로 사용한다.

```text
총예산과 무상유지보수기간은 각각 어떻게 규정되어 있는가?
```

이 질문은 실제로 다음 두 개의 하위 질문이다.

1. 총예산은 얼마인가?
2. 무상 유지보수 기간은 얼마인가?

두 답이 서로 다른 섹션에 있으면 검색 질의도 분리해야 한다. 그러나 현재 구조에서는 하나의 Hybrid 검색 결과만 사용하므로 한 항목의 근거가 검색 순위에서 밀릴 수 있다.

## 4. 전체 질문 단위의 보수적인 답변 판정

현재 생성 프롬프트는 문서 근거가 충분하지 않으면 `is_answerable=false`로 답하도록 구성되어 있다.

복수 항목 질문에서 두 항목 중 하나만 검색된 경우 다음과 같은 문제가 발생할 수 있다.

```text
예산 근거: 발견
유지보수 기간 근거: 미발견
최종 판단: 전체 질문 답변 불가
```

실제로는 다음처럼 답해야 한다.

```text
총예산: 2,000,000,000원입니다.

무상 유지보수 기간: 현재 검색된 근거에서는 확인하지 못했습니다.
```

확인된 항목까지 버리는 전체 거절 방식이 부분 답변 및 오거절의 주요 원인이다.

## 5. RAGAS 평가와의 관계

공식 RAGAS 평가 결과는 다음과 같다.

- Faithfulness: 0.6047
- Answer Relevancy: 0.3077
- 답변 가능한 문항을 잘못 거절: 10개
- 인용 없는 답변: 17개

AI가 답변을 거절한 17문항 중 10문항은 Golden Set 기준으로 답변 가능한 질문이었다.

인용이 없는 답변의 평균 결과는 다음과 같다.

- Faithfulness: 0.235
- Answer Relevancy: 0.000

따라서 UI에서 재현된 현상은 개별적인 화면 오류가 아니라 평가에서 이미 확인된 검색·생성 파이프라인 문제다.

## 6. 필요한 처리 흐름

현재 흐름:

```text
사용자 질문
  → 질문 전체를 한 번 검색
  → 상위 5개 청크
  → LLM 답변
```

필요한 흐름:

```text
사용자 질문
  → 요구 항목 분해
  → 항목별 기술용어·유사어 확장
  → 항목별 BM25 / Dense 검색
  → 검색 결과 병합 및 중복 제거
  → 항목별 근거 존재 여부 판정
  → 확인된 항목은 답변
  → 미확인 항목만 별도 표시
```

## 7. 필요한 수정 사항

### 7.1 질문 요구 항목 분해

질문에서 다음 슬롯을 추출한다.

- 금액 및 예산
- 사업기간
- 유지보수기간
- 입찰방법
- 평가비율
- 참가자격
- 법적 근거
- 기능 목록
- 제출물
- 요구사항 번호

예:

```json
{
  "original_question": "총예산과 무상유지보수기간은?",
  "sub_queries": [
    "총예산 사업비 소요예산 추정가격",
    "무상유지보수 무상 하자보수 유지관리 기간"
  ]
}
```

### 7.2 기술용어 및 유사 표현 확장

질문의 핵심 용어를 RFP 문서에서 사용하는 표현으로 확장한다.

| 사용자 표현 | 확장할 문서 표현 |
|---|---|
| 예산 | 사업비, 총사업비, 소요예산, 추정가격 |
| 유지보수 | 하자보수, 유지관리, 안정화 지원 |
| 사업기간 | 과업기간, 수행기간, 계약기간 |
| 자격 | 참가자격, 입찰참가자격, 자격요건 |
| 평가 | 기술평가, 가격평가, 종합평가 |
| 벌금 | 지체상금, 위약금, 손해배상 |

### 7.3 항목별 검색

분해한 각 하위 질문을 별도로 검색한다.

```text
검색 1: 총예산 + 사업비 + 소요예산
검색 2: 무상 유지보수 + 하자보수 + 유지관리 기간
```

각 검색 결과에서 상위 청크를 가져온 뒤 통합하고 중복을 제거한다.

### 7.4 검색 범위 확대

- 기본 top-k를 5에서 10으로 확대
- 요구사항 번호가 포함된 청크 우선
- 금액, 날짜, 기간이 포함된 청크 우선
- 동일 문서 안에서 인접 청크 확장
- 하위 질문별 최소 검색 결과 수 보장

### 7.5 부분 답변 지원

질문 전체가 아니라 항목별로 답변 가능 여부를 판정한다.

```text
총예산: 확인됨
무상 유지보수기간: 확인됨
입찰방법: 미확인
```

확인된 항목은 답하고 미확인 항목만 명시적으로 구분한다.

### 7.6 직접적인 답변 형식

답변의 첫 줄부터 사용자가 요구한 값을 제시한다.

권장 형식:

```text
총예산: 2,000,000,000원입니다.

무상 유지보수 기간: 검수 완료일로부터 1년입니다.

근거: 사업개요 3페이지, 유지보수 조건 52페이지
```

피해야 할 형식:

```text
질문에 대한 구체적인 내용은 문서에서 확인해야 하나...
다만...
일반적으로...
```

## 8. 구현 우선순위

1. UI 질문의 기본 검색 top-k를 10으로 확대
2. 예산, 기간, 유지보수 등 주요 RFP 용어 사전 추가
3. 복수 항목 질문 분해
4. 하위 질문별 검색 결과 통합
5. 전체 거절 대신 부분 답변 적용
6. 답변 항목별 인용 연결
7. Golden Set의 오거절 10문항으로 회귀 테스트

## 9. 완료 조건

다음 조건을 만족하면 개선이 적용된 것으로 판단한다.

- 답변 가능한 문항의 전체 거절이 감소함
- 복수 항목 질문에서 요구 항목별 답변이 분리되어 표시됨
- 일반 표현과 기술용어가 달라도 동일한 근거를 검색함
- 답변의 각 항목에 PDF 페이지 인용이 연결됨
- 기존 오거절 10문항에서 확인 가능한 항목을 답변함
- UI 질문과 Golden Set 평가가 동일한 검색 설정을 사용함
