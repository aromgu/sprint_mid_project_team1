# RFP Action Copilot 사용자 가이드

## 1. 접속

운영자가 공유한 ngrok 주소를 Chrome 또는 Edge에서 연다.

```text
https://<공유받은-ngrok-주소>
```

1. ngrok 안내 화면이 나타나면 **Visit Site**를 누른다.
2. 로그인 창에 공유받은 사용자명과 비밀번호를 입력한다.
3. 애플리케이션 화면이 나타나면 분석할 RFP를 선택한다.

> ngrok 무료 안내 화면은 첫 접속 시 정상적으로 표시된다. 같은 브라우저에서는
> 한 번 통과한 뒤 일정 기간 다시 나타나지 않을 수 있다.

접속되지 않으면 운영자에게 다음을 확인한다.

- backend와 frontend가 실행 중인지
- ngrok tunnel이 실행 중인지
- 현재 공유 URL과 계정 정보가 맞는지

## 2. 문서 선택

왼쪽 상단의 **파일 목록 열기**를 누른다.

- 문서 이름 검색
- 날짜순 또는 이름순 정렬
- 분석할 RFP 선택

문서를 바꾸면 각 업무 탭도 선택한 문서를 기준으로 갱신된다.

## 3. 업무 화면

### Overview

선택한 RFP의 주요 내용을 한 화면에서 확인한다.

- 제출 및 질의 마감
- 참가 자격 상태
- 실격·감점·불이익 건수
- 제출물 진행 상태
- 우선 조치 항목

요약 카드를 누르면 관련 업무 탭으로 이동한다.

### Go / No-Go

입찰 참여 여부를 결정할 때 우선 확인해야 할 항목을 보여준다.

- 참가 자격
- 실격 조건
- 감점 조건
- 위약금, 손해배상, 계약 해지 등 불이익

각 카드에서 검토 상태를 변경할 수 있다. 카드를 누르면 우측에 해당 원문
페이지가 열린다.

### 실행 준비

준비해야 할 항목을 두 영역으로 구분한다.

- **입찰 제출서류**: 제안서, 가격제안서, 실적증명서 등 입찰 단계 제출물
- **사업 수행 산출물**: 수행계획서, 보고서, 매뉴얼, 교육자료 등 계약 이후 산출물

카드에는 문서에서 추출한 제목, 핵심 조건, 형식, 수량과 진행 상태가 표시된다.
카드를 누르면 우측 원문 페이지가 열리며, 상태 선택 메뉴에서 미착수·진행 중·완료로
변경할 수 있다.

### 요구사항

요구사항을 성격별로 확인한다.

- 기능
- 품질·보안
- 수행·계약

요구사항 ID 또는 내용으로 검색할 수 있다. 각 카드는 고유번호, 요구사항 명칭,
세부 내용과 분류를 표시하며, 누르면 해당 표가 있는 원문 페이지로 이동한다.

### AI 질문

선택한 문서를 근거로 자유롭게 질문한다.

질문 예시:

- 입찰 참가 자격과 필수 업종코드는?
- 실격 또는 감점 조건은?
- 반드시 제출해야 하는 서류는?
- 보안 요구사항을 요약해줘.
- 계약 후 제출해야 하는 산출물은?
- 하자보수 기간과 조건은?

데모에서는 **Gemini Flash-Lite** 사용을 권장한다. AI 답변 아래의 근거 버튼을
누르면 우측 원문 페이지로 이동한다. 새로운 대화를 시작하려면 **대화 초기화**를
누른다.

## 4. 원문 확인

화면 우측의 **EVIDENCE / 원문 확인** 영역에서 분석 결과를 검증한다.

- 이전·다음 버튼으로 페이지 이동
- 검색창으로 원문 문구 검색
- 가운데 경계를 드래그해 원문 영역 너비 조절
- 카드 또는 AI 인용 버튼으로 근거 페이지 열기

AI 요약이나 판정만 사용하지 말고 최종 의사결정 전에는 반드시 원문을 확인한다.

## 5. 내부 평가 화면

내부 평가 화면은 일반 업무 기능이 아니라 Advanced RAG의 검색·답변 품질을
검토하는 팀 내부용 화면이다.

```text
https://<공유받은-ngrok-주소>/internal/evaluation
```

### Overview

Golden Set 104개 질문의 전체 평가 상태를 보여준다.

- Faithfulness
- Answer Relevancy
- Fact Coverage
- 파이프라인 실행 상태

### 시스템 모듈

요청이 처리되는 구조와 각 모듈의 입력·출력을 설명한다.

```text
React UI → FastAPI → RAGClient → Main Advanced → Advanced Chroma → LLM
```

### Chunk / Index

Advanced 데이터와 Chroma index 상태를 확인한다.

- 전체 chunk 및 문서 수
- 평균 token 수
- embedding 누락
- 중복 chunk ID
- collection과 embedding model

### Retriever

질문에 맞는 원문 근거를 찾는 검색 성능을 확인한다.

- Hit@1/3/5
- Fact Coverage@5
- MRR@10
- 검색 latency

### Generation / RAGAS

104개 문항별 답변과 평가 결과를 확인한다.

- 문서 및 질문 유형 필터
- Faithfulness 또는 Relevancy 저점 필터
- 잘못 거절 및 인용 없음 필터
- Golden 답변과 AI 답변 비교
- 사용된 citation과 검색 chunk 확인

문항 행을 누르면 상세 화면이 열린다.

### E2E / Operations

전체 동작과 운영 지표를 확인한다.

- 답변 가능 판정 정확도
- 인용 포함 답변률
- 평균 및 P95 응답시간
- 답변 생성 추정 비용

## 6. 평가 지표 해석

### Faithfulness

AI 답변이 검색된 원문 근거에 의해 뒷받침되는 정도다. 현재 Top-10 평가 결과는
약 `84.8%`다.

### Answer Relevancy

답변이 질문의 요구에 얼마나 직접 대응하는지를 나타낸다.

- 전체 평균: 약 `37.4%`
- 정상 답변 평균: 약 `44.3%`

전체 평균에는 근거가 일부만 확인된 부분 답변과, 문서에 정보가 없어 정상적으로
답변을 거절한 문항도 포함된다. RAGAS는 이러한 신중한 응답에도 낮은 점수를 줄 수
있으므로 전체 평균만으로 시스템 품질을 판단하지 않는다.

다음 항목을 함께 확인한다.

- 정상 답변의 Answer Relevancy
- Faithfulness
- 잘못 거절한 문항 수
- 인용 근거 유무
- 문항별 Golden 답변과 AI 답변

### Fact Coverage

질문에 필요한 핵심 사실이 검색 결과에 포함된 비율이다. 여러 조건을 동시에 묻는
질문에서는 단순 검색 성공 여부와 함께 Fact Coverage를 확인한다.

### Answerability

문서 근거만으로 답변할 수 있는지를 올바르게 판단한 정도다. 화면에서는 답변,
부분 답변, 답변 불가의 3단계로 표시한다.

> 내부 평가 화면은 저장된 Top-10 Golden 평가 결과를 읽는다. 화면을 열거나 문항을
> 조회하는 것만으로 104개 답변을 다시 생성하거나 추가 평가 비용이 발생하지 않는다.

## 7. 보안 및 사용 유의사항

- 공유 URL과 비밀번호를 허가되지 않은 사람에게 전달하지 않는다.
- API key, 계정 비밀번호, 개인정보 및 기밀자료를 질문에 입력하지 않는다.
- 업로드 PDF에 민감정보가 포함되어 있지 않은지 먼저 확인한다.
- 외부 사용자의 문서 업로드와 AI 질문은 API 사용량과 비용을 발생시킬 수 있다.
- AI 답변은 참고용이며 입찰·계약 의사결정 전 원문을 최종 확인한다.
- 사용이 끝나면 브라우저를 닫고, 운영자는 공유 종료 후 ngrok tunnel을 종료한다.
