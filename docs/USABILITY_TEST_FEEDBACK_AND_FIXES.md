# RFP Action Copilot MVP 사용성 테스트·수정 결과

작성일: 2026-07-22  
대상: Handover v3 MVP frontend/backend

## 1. 테스트 범위

실제 UI에서 다음 흐름을 기준으로 확인했다.

- 문서 선택 및 Overview 표시
- Go / No-Go(위험) 분석
- 참가 자격 분석 및 상태 변경
- 실행 준비(제출물) 분석 및 상태 변경
- 요구사항 분석 및 근거 페이지 이동
- AI 질문·답변·인용
- 문서 내 페이지 검색
- TOC(목차)와 페이지 뷰어 이동
- 서버 시작 및 검색 지연시간

## 2. 사용자 피드백과 조치

| 구분 | 사용성 피드백/발견 | 원인 | 조치 | 결과 |
|---|---|---|---|---|
| 서버 시작 | Uvicorn 실행 시 `Loading weights`가 표시됨 | Dense 임베딩 모델을 시작 시 메모리에 로딩 | 정상 동작임을 문서화하고 Dense prewarm 유지 | 최초 검색 지연 감소 |
| 지연시간 | 초기 검색이 약 5초로 느림 | Dense 모델 cold start 및 OpenAI 호출 | Dense prewarm, 컨텍스트 12,000자, 출력 토큰 700, 결과 캐시 적용 | 시작 약 3초, warm 검색 약 0.1초 |
| Overview | `502 BadRequestError` 발생 | Overview Structured Output 스키마의 자유형 dict 호환성 문제 가능 | 위험 수·제출물 진행률을 고정 필드 모델로 변경, 예외 로그 추가 | API 테스트 통과 |
| Overview | 분석 결과가 없다고 표시됨 | 프론트가 `action_items`만 확인하고 요약 필드를 무시 | Overview 전용 요약 카드 구현 | 마감일·자격·위험·제출물 요약 표시 |
| Overview | `확인 필요`가 과도하게 표시됨 | RFP 본문에 없는 값을 기본값으로 표시 | 제출일 `입찰공고 참조`, 질의일 `RFP 본문 미기재`로 변경 | 문서 미기재와 추출 실패를 구분 |
| 봉화군 문서 | 제출·질의 마감일이 보이지 않음 | 해당 RFP는 날짜를 본문에 기재하지 않고 공고문을 참조하도록 명시 | p.10, p.59~60 원문 확인 | 현재 표시는 정상 |
| 참가 자격 | 분석 결과가 비어 있음 | 검색 근거는 있으나 LLM이 빈 배열을 반환할 수 있음 | 근거가 있으면 `참가 자격 확인 필요` fallback 항목 생성 | 빈 화면 방지 |
| 문서 검색 | 검색 후 결과 목록이 계속 남음 | 결과 선택 후 상태 초기화 없음 | 결과 페이지 클릭 시 결과·검색어 자동 초기화 | 페이지 확인 후 검색 UI 정리 |
| 상태 저장 | 참가 자격/제출물 상태 저장 확인 필요 | PATCH API와 새로고침 검증 필요 | 상태 변경 후 재조회·새로고침을 검증 시나리오로 정의 | 후속 E2E 확인 대상 |
| TOC | 목차가 모든 페이지를 포함하는지 혼동 | TOC는 페이지 목록이 아니라 인식된 heading 색인 | 제목·페이지 기반 색인임을 문서화 | 첫·중간·마지막 항목 이동 확인 방식 정의 |

## 3. 봉화군 RFP 확인 결과

대상 문서: `상_3` / 봉화군 재난통합관리시스템 고도화 사업

- p.10: `제출기한: 입찰공고 참조`
- p.59: `접수마감: 공고문에 따름`
- p.59: `제출방법: 공고문 참조`
- p.60: 질의는 봉화군 안전건설과에서 답변한다고만 기재

따라서 제출 마감일·질의 마감일이 날짜로 표시되지 않는 것은 RFP 추출 실패가 아니라 원문 특성이다. 정확한 날짜는 별도 나라장터 입찰공고에서 확인해야 한다.

## 5. 남은 검증 항목

1. 참가 자격 상태 변경 후 브라우저 새로고침하여 유지 여부 확인
2. 실행 준비 상태 변경 후 새로고침하여 유지 여부 확인
3. 모든 문서 ID에서 Overview·분석 탭 응답 확인
4. OpenAI timeout/API 오류 시 UI 메시지 확인
5. Golden set 수령 후 RAGAS 기반 검색·답변 평가 연결

## 6. 실행 참고

```bash
uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
cd frontend && npm run dev
```

코드 변경 후에는 백엔드 재시작과 브라우저 강력 새로고침(`Ctrl+Shift+R`)을 수행해야 기존 분석 캐시가 아닌 최신 결과를 확인할 수 있다.
